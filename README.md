# ニンゲン家具 (Ningen Kagu)

家具に変身できる丸い生き物 **「カグミン」** を操作して、一つ目の見回りモンスターから **60秒間** 見つからずに生き残る、ブラウザだけで動く3Dステルスゲームです。
**STAGE 1 リビング**・**STAGE 2 教室**・**STAGE 3 美術室**の3面構成で、前のステージをクリアすると次へ進みます。

外部モデル・外部APIを使わず、Three.js のプリミティブ形状だけで作られています。
ビルド不要で、静的HTTPサーバーや GitHub Pages からそのまま公開できます。

## 遊び方

| 操作 | PC | スマホ | ゲームパッド |
|---|---|---|---|
| 移動 | `W` `A` `S` `D` / 矢印キー | 画面左の仮想スティック | 左スティック |
| 視点 | 画面をドラッグ | 画面をドラッグ | 右スティック |
| 擬態 | `E` / `Enter` | 右下の「擬態」ボタン | A / × ボタン |
| ポーズ切替 | `Q` / `Space` / `Shift` | 右下の「ポーズ」ボタン | B / ○ ボタン |
| おとり | `R` | 右下の「おとり」ボタン | X / □ ボタン |
| 一時停止 / 再開 | `Esc` / `P` | 右上の ⏸ ボタン | Start / Select |
| 開始・リトライ | `Enter` / `Space` | 画面のボタン | A / × ボタン |

1. 家具や壁のそばで **擬態** を押すと、その物の色と材質をコピーします。
2. **ポーズ** で 直立 / Tポーズ / Yポーズ / しゃがみ を切り替えます。
   物によって「似合うポーズ」があり、合っていると HUD が **ポーズ◎** になります。
3. 鬼に怪しまれると、ときどき **家具検査モード** が始まります。動かずに耐えれば大きなボーナス。
4. 今向いている方向へ **おとり** を投げると、鬼の注意をそこへ引きつけられます（1ゲームに数回だけ）。
5. 60秒逃げ切れば勝ち。鬼の警戒度が振り切れたら負け。

鬼が画面の外にいるときは、画面のふちに **👁 の矢印** が出てどちらにいるかを教えてくれます。
一時停止するとタイマーも鬼も止まります（タブを離れたときは自動で一時停止します）。

ゲームパッドは USB / Bluetooth で接続して何かボタンを押すかスティックを動かすだけで認識されます。
タイトル画面でも A / × ボタンでゲームを開始できます。

## 設定

タイトルの「設定」から次を調整できます。設定内容はブラウザに保存され、次に開いたときも引き継がれます。

| 項目 | 内容 |
|---|---|
| サウンド | BGM・効果音をまとめてオン / オフ |
| BGM音量 / 効果音音量 | それぞれ 0〜100% で個別に調整 |
| 視点感度 | ドラッグ・ゲームパッド右スティックの視点操作の速さを 50〜200% で調整 |
| Y軸反転 | 視点の上下方向を反転 |

## ステージ

| | STAGE 1 リビング | STAGE 2 教室 | STAGE 3 美術室 |
|---|---|---|---|
| 擬態対象 | ソファ・棚・観葉植物など約15種 | 机3列×3・ロッカー・黒板など約30種 | 石膏像・イーゼル・画材棚など約16種 |
| 鬼の巡回路 | 部屋を大きく周回 | 机の間の通路を縫うルート | 石膏像とイーゼルを避けて壁沿いを周回 |
| ステージイベント | 📺 テレビがついた！ | 🔔 チャイム！ | 💡 照明が消えた！ |

STAGE 3 の石膏像とイーゼルのキャンバスはどちらもほぼ白色。色を合わせるだけでは他の擬態対象と見分けがつかず、**ポーズまで合わせて初めて成立**します（石膏像は Y ポーズ、イーゼルは T ポーズ）。

- 前のステージをクリアすると次のステージへ進みます。負けた場合は同じステージをリトライします。
- 到達したステージはブラウザに保存され、次に開いたときもその面から再開します。
- ベストスコアはステージごとに別で記録されます。

## ステージイベント（プレイ中に部屋が変わる）

1ゲームに **1〜2回**、そのステージ専用のイベントがランダムに発生します。
開始直後には起きません（最短でも開始10秒以降）。イベント終了後はクールダウンが入り、
2つのイベントが同時に走ることはありません。残り5秒以下では新しく発生しません。

| ステージ | イベント | 鬼への影響 | プレイヤーの得 | リスク |
|---|---|---|---|---|
| STAGE 1 リビング | 📺 **テレビがついた！** | テレビ前へ移動して画面を見る。見抜く力が大きく下がる | 家具から家具へ移る絶好のチャンスタイム | 完全な無敵ではない。鬼の正面を横切ると振り向かれる |
| STAGE 2 教室 | 🔔 **チャイム！** | 黒板・教卓の前まで移動し、数秒そちらを向く | 机の列をまたぐルートが開く | 鬼の位置が大きく変わるので、その後の巡回路が読みにくくなる |
| STAGE 3 美術室 | 💡 **照明が消えた！** | 部屋が暗くなり、視認距離・視界の広さ・発見速度が下がる | 暗い間は移動しやすい | 点灯の1秒前に「⚠ 明かりが戻る！」が出る。**点灯の瞬間に動いていると警戒度が上がる** |

イベントは「発生＝自動的に得」ではなく、**判断する時間** として設計しています。
使いどころを間違えれば、かえって見つかりやすくなります。

鬼の性格タイプによって反応も少し変わります。

- 👁 見張り鬼：イベント中も周囲をちらちら警戒する（気の取られ方が浅い）
- 💨 猪突猛進鬼：イベント地点へ素早く飛んでいく（そのぶん元の場所ががら空きになる）
- 🧐 疑り深い鬼：イベント後すぐには巡回へ戻らず、その場で周囲を確認する

**新しいステージへイベントを足すとき**は次の2か所だけを触ります。

1. `js/stage.js` … そのステージの `eventRig`（鬼が見る位置・立ち位置候補・使う3Dオブジェクト）
2. `js/stageEvents.js` … `STAGE_EVENTS` にステージIDのキーを1つ追加

開発用に、現在のイベント状態は `window.__ningenkagu.game.stageEvent`（要約は `__ningenkagu.stageEventInfo()`）で確認でき、
`window.__ningenkagu.triggerStageEvent()` で現在ステージのイベントを強制発生できます（通常UIには出ません）。

## 鬼の性格（毎ゲーム変わる）

ゲーム開始のたびに、鬼の **性格タイプ** が3種類から均等確率で1つ選ばれます。
リトライでもステージ移行でも選び直されるので、同じステージでも毎回すこし違う60秒になります。
開始直後に画面中央へ2秒ほど「今回の鬼」が表示されるので、それを見てから作戦を決めてください。

| タイプ | 強み | 弱み | 立ち回り |
|---|---|---|---|
| 👁 **見張り鬼** | 視界が長く広い。遠くからでも見抜いてくる | 移動が遅い | 「遠いから安全」は通じない。遮蔽物を挟み、離れていても擬態を完成させておく |
| 💨 **猪突猛進鬼** | 足が速く、巡回テンポも速い | 視界が短く、家具の見分けが雑。検査もあまり来ない | 見つかりそうになってから隠れ直す「逃げ」の判断が有効 |
| 🧐 **疑り深い鬼** | すぐ **家具検査** に来る。検査も丁寧で長い | 移動が遅く、視界もやや短い | 適当な擬態は通らない。色・ポーズ・静止をきちんと合わせる |

3種類は「強さ」ではなく **攻略法** が違うように調整してあります（得意な能力の裏に必ず弱点があります）。
性格は既存の巡回・視界・家具検査に **倍率** を掛けるだけで、仕組み自体は1つのままです。

## 家具検査モード（鬼の心理戦）

鬼に怪しまれても、すぐ発見されるわけではありません。
一定の確率で鬼が近づいてきて、**その家具（あなた）が本物かどうかを確かめる**「家具検査モード」に入ります。
検査中は頭の上に **「？」**、視界コーンが **オレンジ** になり、鬼が目を細めて首をかしげます。

鬼の動きは毎回変わります。

| 動作 | 内容 |
|---|---|
| 接近して凝視 | 1.5〜2.5m まで近づいて、じっと見つめる |
| 横から確認 | 左右へ回り込み、別の角度から確かめる |
| 背中を向けるフェイント | やめたふりをして背を向け、**急に振り返る** |
| 突然の振り返り | よそ見からの素早い向き直り |

- 背を向ける／よそ見の直前には **「！」マークと短い効果音** の予兆が出ます。ここで止まれば間に合います。
- **検査成功**（動かずに耐え切る）→ 警戒度が大きく下がり、`完全に家具だと思われた！ +800` のボーナス。
- **検査失敗**（移動・ポーズ変更・擬態変更・擬態成功度が低い）→ 警戒度が上がり、鬼はもうしばらく見張ります。
  失敗そのもので即発見にはなりませんが、**もともと警戒度が高い状態で大きく動くと発見**されます。
- 検査は連続では起きません（1プレイで数回程度）。残り時間が少ないときは短く切り上げます。
- 判定には新しい仕組みではなく、既存の **擬態成功度**（色・静止・ポーズ・距離）をそのまま使います。

## 擬態成功度の仕組み

HUD の「擬態 ○○%」は次の4つで決まります。

| 要素 | 内容 |
|---|---|
| 色 | **鬼から見てプレイヤーの背後にある物** の色と、自分の色がどれだけ近いか |
| 静止 | 完全に止まっているほど高い（動くと即座に下がる） |
| ポーズ | 擬態した物に合ったポーズかどうか |
| 距離 | 擬態した物の近くにいるかどうか |

擬態成功度が高いほど鬼に気づかれにくくなりますが、**100%にはならない**ので絶対安全にはなりません。

## 足音（聴覚）

鬼は視界だけでなく **足音** でも気づきます。近くで速く動くほど大きな音が出て、鬼の視界に入っていなくても壁越しに勘づかれます。

- **しゃがみ** は移動そのものが遅いうえ、足音自体も小さいので一番静か。直立ダッシュや T/Y ポーズでの移動は大きく響きます。
- 音は距離で急に減衰するので、鬼からある程度離れていれば走っても問題ありません。
- 大きな音を立てると画面に「足音が聞こえた…！」と出ます。ここで止まるかしゃがめば間に合います。
- 「見抜く力」の強い性格タイプ（👁 見張り鬼）は耳もよく、雑な 💨 猪突猛進鬼は音にも気づきにくいなど、鬼の性格差がそのまま反映されます。

## おとり

`R` / 右下の「おとり」ボタンで、今向いている方向へ物音を投げ、鬼の注意をそこへ引きつけられます。

- 1ゲームに **2回** まで。連続では使えず、少しクールダウンがあります。
- 鬼は数秒間その場所へ気を取られます（テレビやチャイムと同じ仕組み）。その間に別方向へ逃げたり擬態し直したりできます。
- 鬼に既に見つかっている・家具検査中・すでに何かに気を取られている最中は使えません。
- おとりの間もこちらの姿が視界に入れば普通に気づかれます。鬼から離れた場所を狙いましょう。

## スコア（見落としポイント）

鬼の視界に入っているのに気づかれていない間、スコアが増え続けます。

- 鬼に近いほど倍率アップ
- 鬼の視線の中心にいるほど倍率アップ
- 警戒度が高いほど倍率アップ
- 目の前でじっと見つめられて耐え切ると **見逃しボーナス**（+300 ずつ増加）
- 家具検査モードを耐え切ると **検査ボーナス**（+800 ずつ増加／見逃しボーナスとは別枠）
- ベストスコアはステージごとにブラウザへ保存され、次に開いたときも残ります

つまり、安全な隅に隠れるより **鬼の目の前で家具になりきる** 方が高得点です。

## 構成

```
index.html          エントリポイント
css/style.css       UI / HUD / スマホ操作
js/main.js          レンダラ・ライト・ゲームループ・UI配線
js/game.js          ゲーム進行、擬態成功度、発見判定、スコア
js/stage.js         部屋と家具の生成、擬態対象、当たり判定
js/player.js        カグミンの見た目・表情・ポーズ
js/oni.js           一つ目の見回りモンスター（巡回・視界・遮蔽判定・家具検査モード・性格タイプ）
js/stageEvents.js   ステージ固有のランダムイベント（テレビ / チャイム / 消灯）
js/gameState.js     ゲーム状態（title / playing / paused / win / lose）の通知口
js/input.js         キーボード / マウス / タッチ / ゲームパッド入力
js/hud.js           画面表示
js/effects.js       擬態エフェクト、対象マーカー
js/audio.js         WebAudio で合成する効果音（音素材ファイル不要）
js/battleBgm.js     タイトル / プレイ中のBGM切替（gameState を購読して追従）
js/titleMenu.js     スマホでのタイトルカード操作
assets/audio/       BGM（タイトル曲・戦闘曲。効果音は audio.js が合成するので別途無し）
assets/ogp.jpg      SNS共有カード用の画像（実際のタイトル画面から生成）
assets/icon-*.png   ホーム画面に追加したときのアプリアイコン
manifest.json       PWA としてインストールするための情報
vendor/three/       Three.js r180 (MIT)
```

## 動かす

アプリサーバーやビルド処理は不要ですが、ES モジュールを使うため `file://` ではなく HTTP で開いてください。

```sh
python3 -m http.server 8000
# http://localhost:8000/
```

## GitHub Pages で公開

リポジトリの Settings → Pages で Branch にこのブランチ、フォルダに `/ (root)` を指定するだけです。
（Jekyll の処理を避けるため `.nojekyll` を置いてあります）

スマホでは「ホーム画面に追加」でフルスクリーンのアプリとして起動できます（`manifest.json`）。

**別の場所へ公開する場合**は、`index.html` の次の3か所を新しいURLへ差し替えてください。
OGP の仕様上、`og:image` と `og:url` は絶対URLである必要があり、相対パスにすると
SNSでカードが表示されません（ローカルでは何も起きないので気づきにくい箇所です）。

- `<link rel="canonical">`
- `<meta property="og:url">`
- `<meta property="og:image">`

共有用の画像（`assets/ogp.jpg`）とアプリアイコン（`assets/icon-192.png` / `icon-512.png`）は
実際のゲーム画面から生成したものです。作り直す場合はローカルサーバーを立てた状態で
Playwright からタイトル画面を 1200x630 で撮り直してください。

## テスト

ゲーム本体はビルド不要ですが、テストは Node と依存パッケージを使います。

```sh
npm install
npm run test:unit   # 純粋関数のユニットテスト（Node標準の test ランナー、依存なし）
npm run test:e2e    # 実ブラウザでの起動・状態遷移のスモークテスト（Playwright）
npm test            # 両方まとめて実行
```

| | 内容 | 場所 |
|---|---|---|
| ユニットテスト | `utils.js` の各関数、`alertLevel`、`resolveCollisions`、`gameState.js` の状態通知、`audio.js` のミュート通知、`disposeObject3D` の解放範囲 | `tests/unit/` |
| E2Eスモークテスト | 起動確認、ステージ切替・タイトル復帰を繰り返してもGPUリソース（ジオメトリ・テクスチャ）が増え続けないこと、BGMがゲーム状態に正しく追従すること | `tests/e2e/` |

`npm run test:e2e` は初回のみブラウザのダウンロードが必要な場合があります（`npx playwright install chromium`）。GitHub Actions では `.github/workflows/ci.yml` が push・PRごとに両方を自動実行します。
